# Повторная проверка безопасности, устойчивости и скорости

Проверка начата с коммита `6bdd92b`; выполнена 4–5 ноября 2026 года. Три субагента независимо рассмотрели безопасность, сбои/восстановление и путь передачи данных; основной агент воспроизвёл находки и интегрировал исправления. Использованы локальный Graphify, текущие исходники, рекомендации gstack review/investigate и изолированные тесты. Это проверка кода и локальных стендов; полного формального receipt gstack и независимого пентеста нет.

## Подтверждённые находки

| Проблема | Возможный эффект | Исправление |
|---|---|---|
| Явные ACL Everyone/Users сохранялись у существующего приватного каталога Windows | Чтение нового plaintext-экспорта другим локальным пользователем | Полная замена DACL разрешением владельца, проверка результата до записи; три native Windows-регрессии |
| Неатомарная запись последней рабочей политики firewall | После ошибки диска пустой checkpoint мог привести к транзакции только удаления защитных таблиц | Атомарные durable-записи, проверка обеих таблиц с default-drop и возврат к rescue при повреждении checkpoint |
| Каталог `/run/vpn-service` создавался только при установке | После reboot sandbox systemd мог завершиться до запуска applicator | `RuntimeDirectory=vpn-service`, права 0700 до запуска процесса |
| Остановка oneshot-unit оставляла WireGuard в ядре | `systemctl stop vpn-tunnel` сам по себе не прекращал пересылку | `ExecStop` удаляет `vpn0`; точная команда проверена на настоящем kernel-интерфейсе |
| nginx не перезапускался при замене только сертификатов | После `renew-telemetry` агенты и gateway использовали разные PKI | Перезапуск gateway при изменении конфигурации **или** файлов сертификатов |
| Ошибка чтения journal/firewall/revision выглядела как нулевое число инцидентов | Свежие метрики могли скрыть потерю защитной наблюдаемости | Явная метрика `vpn_security_probe_up` и отдельная тревога; ошибку чтения нельзя считать отсутствием событий |

Реальные VPS не затронуты; эксплуатационных ключей в тестах нет. Проверки Windows используют временные синтетические файлы. Native nginx-тест использует две одноразовые PKI и loopback в контейнере без интернета: проверяет обязательный клиентский сертификат, запрет чужого CA, закрытые маршруты и перечитывание сертификатов после reload.

Проверка firewall отвергает пустую/структурно неверную политику и ошибки nft-синтаксиса. Она не аутентифицирует checkpoint и не выявляет каждое синтаксически допустимое изменение правил; root-компрометация остаётся отдельной критической угрозой.

Локально прошли 36 Linux-тестов (из 39 обнаруженных, 3 Windows-пропуска), отдельно 3 native Windows ACL-теста, пять Ansible syntax-check, kernel WireGuard/nft-стенд, настоящий nginx mTLS и проверки панели с 12 тревогами/конфиденциальности журналов. В CI добавлен отдельный Windows job. Результат CI нужно сверять для конкретного коммита; наличие этого документа само по себе не означает успешного удалённого прогона.

## Скорость: измеренный локальный предел доказательства

Изолированный Docker-стенд без интернета, лимиты 2 CPU / 512 МиБ, MTU 1380, настоящий kernel WireGuard и production nftables/NAT. Каждый образец — **3 секунды**, измеряется полученная скорость. Это потоки одного peer, а не разные пользователи.

| TCP-потоки одного peer | Upload, Мбит/с | Download, Мбит/с |
|---|---:|---:|
| 1 | 1191 | 1536 |
| 4 | 1126 | 1456 |

Измерение подтверждает отсутствие очевидного жёсткого ограничения на низкой скорости в проверенном локальном пути. Python, сбор журналов и DPI не обрабатывают каждый пересылаемый пакет; общего небольшого UDP rate limit для VPN нет. Мониторинг на B ограничен примерно 1,9 ГиБ RAM / 3 CPU, Alloy на A — ещё 256 МиБ / 0,5 CPU; эти лимиты не гарантируют запас CPU на реальном VPS.

В тесте не работал полный мониторинг, не было российских операторов и географического маршрута, 30–70 одновременно передающих устройств или длительной нагрузки. Он **не подтверждает** критерий 800 Мбит/с за 60 минут и скорость зарубежного сервера. Прямой veth baseline 62–77 Гбит/с относится к обмену в памяти, не к интернету. Команда, адаптация стенда и наблюдённый результат сохранены локально в исключённой `.state/performance-audit/`.

## Что остаётся проверять на VPS

Фактический reboot/PID1 systemd, повторное применение Ansible, ротацию PKI через весь playbook, DNS/IPv6/kill switch на каждой ОС, отзыв на двух узлах, резервирование, реальные уведомления и восстановление копии. Отдельно измерить пропускную способность, RTT/jitter/loss и CPU steal с работающим мониторингом по [плану приёмки](acceptance.md). Общий провайдер, ручное переключение, офлайн-отзыв и отсутствие внешнего неизменяемого аудита остаются известными ограничениями.

Настройка lifecycle сверена с [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html); необходимость перечитывания конфигурации nginx — с [официальным описанием reload](https://nginx.org/en/docs/control.html).
